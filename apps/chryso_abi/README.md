# chryso_abi

Erlang side of the orchestration ABI: `chryso_abi_codec` and `orchestrator_abi.hrl`, generated by `tools/abi` from `interfaces/orchestrator_abi.zig`. It is a library application with no processes.

The codec is never committed. From the dev shell, `chryso-abi-rebar3` rebuilds the `orchestrator-abi` package:

```bash
# shared vectors, codec cases and PropEr properties
chryso-abi-rebar3 eunit
chryso-abi-rebar3 dialyzer
```

Outside the dev shell, set the package root by hand: 
- `CHRYSO_ABI_GENERATED=$(nix build --no-link --print-out-paths .#orchestrator-abi) rebar3 eunit`.

`rebar.config.script` copies the codec from `erlang/`, `chryso_abi_vectors_tests` reads the vectors from `vectors/`, the same images `tests/host` runs through the C checkers.

Dependencies are pinned for Nix in `rebar-deps.nix` by the rebar3_nix plugin. After changing `deps` or the test profile, regenerate it (the test profile is included because the Nix check runs the property tests):

```bash
rebar3 as test nix lock -o rebar-deps.nix
```
